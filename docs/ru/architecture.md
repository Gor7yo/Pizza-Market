# Архитектура

[English](../en/architecture.md) | **Русский**

Tonir Pizza — интернет-магазин пиццы для рынка Армении. Монорепозиторий pnpm + Turborepo:

```
market/
├── front/                  Next.js 16 (App Router) — витрина + админка      (@market/web)
├── back/                   NestJS 11 + Prisma 7 + PostgreSQL + Redis         (@market/api)
├── packages/
│   ├── shared/             общие контракты: Zod-схемы, DTO-типы, деньги,
│   │                       ценообразование, статусы заказа, коды ошибок      (@market/shared)
│   ├── typescript-config/  базовые tsconfig
│   └── eslint-config/      общий flat-config ESLint
├── docker/                 Dockerfile'ы и init-скрипты
├── docs/
└── docker-compose.yml
```

## Принципы

1. **Сервер — единственный источник истины** для цен, скидок, статусов, ролей и оплаты.
   Клиент присылает только идентификаторы и количества.
2. **Один контракт на обе стороны.** Zod-схемы в `@market/shared` валидируют формы
   во фронтенде (React Hook Form) и запросы в API (`ZodValidationPipe`). Типы ответов
   (`*Dto`) тоже общие — фронт не угадывает форму ответа.
3. **Безопасно по умолчанию.** Любой маршрут API требует аутентификации, если не помечен
   `@Public()`; роли проверяются глобальным guard'ом.
4. **Просто и сопровождаемо** — абстракции только там, где есть реальная точка замены
   (оплата, почта, хранилище, геокодинг, карта, уведомления).

## Фронтенд (`front/`)

| Слой                           | Что                                                                                              | Где                               |
| ------------------------------ | ------------------------------------------------------------------------------------------------ | --------------------------------- |
| Маршрутизация                  | App Router; группы `(store)`, `(auth)`, `admin`                                                  | `src/app`                         |
| Серверные данные               | Server Components + `serverApi()` (кэш данных Next для публичного, `no-store` для персонального) | `src/lib/api/server.ts`           |
| Интерактивные серверные данные | TanStack Query (кэш, инвалидация, optimistic updates, polling)                                   | `src/lib/query`, `src/features/*` |
| Клиентское состояние           | MobX: корзина, конструктор пиццы, UI, оформление заказа                                          | `src/stores`                      |
| Формы                          | React Hook Form + Zod (общие схемы)                                                              | `src/features/*`, `src/app/**`    |
| Стили                          | CSS Modules + дизайн-токены (CSS-переменные), «жидкое стекло»                                    | `src/styles/tokens.css`           |
| i18n                           | next-intl (без префикса в URL, язык в cookie), ru / en / hy                                      | `src/i18n`, `messages/`           |
| Защита маршрутов               | `src/proxy.ts` (Next 16 proxy) + серверная проверка в `admin/layout.tsx` + API                   |                                   |

**Разделение MobX / TanStack Query.** MobX хранит только клиентское состояние:
конфигурации позиций корзины (без цен), выбранные опции конструктора, открытость
корзины, валюту отображения, шаги оформления. Всё серверное (товары, цены корзины,
заказы, пользователь, админ-данные) — в TanStack Query. Цены корзины всегда приходят из
`POST /cart/quote`.

**Фильтры каталога** живут в URL, а не в MobX: страницей можно поделиться, работает
кнопка «назад», первая страница рендерится на сервере (SEO).

**React Compiler** включён. Компоненты-`observer` MobX помечены директивой
`'use no memo'`: компилятор мемоизирует по ссылкам и не видит мутаций observable.

**Браузер обращается только к своему origin.** `next.config.ts` проксирует `/api/v1/*`
на API (rewrite), поэтому auth-cookies first-party, CORS для браузера не нужен,
адрес API не раскрывается.

## Бэкенд (`back/`)

Модульный NestJS. Контроллеры тонкие, бизнес-логика в сервисах.

```
src/
├── config/              env-схема (Zod), типизированный AppConfig
├── common/              ошибки, глобальный фильтр, Zod-пайп и декораторы (+Swagger), guards
├── infrastructure/      prisma, redis, storage (S3), email (Resend/console + BullMQ), queues
└── modules/
    ├── auth/            регистрация, коды, вход, refresh-ротация, Google OAuth, сессии, AuthGuard
    ├── users/           профиль, аватар, адреса, админка пользователей
    ├── catalog/         публичный каталог + админка товаров/категорий/ингредиентов/бортов
    ├── pricing/         PricingService (валидация конфигурации + цены), PromoService, QuoteService
    ├── cart/            серверная корзина, слияние, quote
    ├── orders/          создание заказа (транзакция + идемпотентность), статусы, админка
    ├── payments/        абстракция PaymentProvider + MockPaymentProvider
    ├── notifications/   подписка на доменные события → каналы (email; задел push/SMS)
    ├── reviews/         отзывы только после покупки, модерация, пересчёт рейтинга
    ├── favorites/ promo/ settings/ dashboard/ audit/ geo/ maintenance/ dev/
```

### Ценообразование

`PricingService.resolve()` принимает `{productId, sizeId, crustId, removedIngredientIds,
extraIngredientIds, quantity}` и для каждой позиции проверяет:
товар существует, не в архиве, доступен; размер принадлежит товару; борт разрешён;
убираемые ингредиенты — из состава и `isRemovable`; добавки — роли `EXTRA` и доступны.
Затем считает `base + size + crust + extras` общими функциями из `@market/shared/pricing`.
`QuoteService` добавляет промокод, доставку и итог. Тот же код работает в транзакции
создания заказа.

### Создание заказа

`OrdersService.create()` в одной транзакции Prisma:
1–7. пересчёт корзины, проверка доступности, опций, промокода, минимальной суммы, доставки;
8–9. заказ + позиции со **снимком** (название, размер, борт, ингредиенты, цены); 10. платёж через `PaymentsService` → `PaymentProvider`; 11. очистка серверной корзины; 12. начальная запись истории статусов.

Идемпотентность: заголовок `Idempotency-Key` (UUID) + уникальный индекс
`(userId, idempotencyKey)` + SHA-256 тела запроса. Повтор с тем же ключом возвращает
тот же заказ (200), с другим телом — `409 IDEMPOTENCY_CONFLICT`. Гонка двух одинаковых
запросов разрешается уникальным индексом.

### Статусы заказа

Граф переходов — в `@market/shared/order-status.ts` (используют и API, и UI).
Меняет статус только `OrderStatusService.transition()`: оптимистическая блокировка по
текущему статусу, история, аудит (для админа), синхронизация платежа (наличные → оплачен
при выдаче; отмена оплаченного → возврат через провайдера), событие `order.status_changed`
после коммита.

### Фоновые задачи (BullMQ)

| Очередь       | Задачи                                             | Свойства                                                                                                            |
| ------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `email`       | все транзакционные письма                          | 5 попыток, экспоненциальная задержка; jobId для идемпотентности; письма с секретами удаляются сразу после обработки |
| `maintenance` | ежедневная очистка истёкших сессий, кодов, токенов | job scheduler (одна задача на кластер), идемпотентна                                                                |

### Redis

Используется только там, где это обосновано: общий rate limiting (`RedisThrottlerStorage`),
блокировка входа после неудачных попыток, отозванные сессии (мгновенная инвалидация
access-токенов), cooldown'ы кодов и сброса пароля, состояние OAuth, кэш настроек магазина
(читаются на каждый quote) и геокодинга, очереди BullMQ.

### Хранилище файлов

`FileStorage` (абстрактный класс) → `S3FileStorage` (AWS S3 / Cloudflare R2 / MinIO, в разработке — SeaweedFS). `ImageService`
декодирует загрузку через sharp (не доверяя MIME/расширению), убирает метаданные,
поворачивает по EXIF, уменьшает и перекодирует в WebP. Ключи содержат UUID →
`Cache-Control: immutable`.

### Платежи

`PaymentProvider` — контракт `createPayment` / `refund`. Сейчас реализован только
**mock-провайдер**: платёж создаётся в `PENDING`, покупатель попадает на тестовую
страницу `/checkout/pay/:id`, результат применяет сервер (`mock-confirm` играет роль
callback'а провайдера). Реальный провайдер (армянский эквайринг, Stripe) должен
подтверждать оплату только подписанным server-to-server callback'ом.

### Уведомления

Заказы публикуют доменные события (`@nestjs/event-emitter`), `NotificationsService`
подписан на них и рассылает по каналам `NotificationChannel[]`. Сейчас канал один —
email; push/SMS добавляются новым классом без изменений в заказах.

## Деньги и валюты

Все суммы — **целые числа в минимальных единицах** валюты магазина (`STORE_CURRENCY`,
по умолчанию AMD с 0 знаков после запятой; USD/RUB — 2). Плавающая точка для денег
не используется: проценты — целочисленным округлением, конвертация — через BigInt.
USD/RUB показываются только как «≈» по курсам, которые админ задаёт вручную (дата
обновления хранится). Заказы всегда в валюте магазина.

## Границы безопасности

| Угроза                            | Защита                                                                                               |
| --------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Подмена цен/скидок/статусов/ролей | сервер пересчитывает всё, strict-схемы отвергают лишние поля (mass assignment)                       |
| IDOR                              | все пользовательские запросы фильтруются по `userId`; чужое = 404                                    |
| CSRF                              | SameSite=Lax cookies + JSON-only + проверка `Origin`/`Referer` (`OriginGuard`)                       |
| XSS                               | React-экранирование, CSP, HttpOnly-cookies (токены недоступны JS)                                    |
| Перебор                           | глобальный и точечный rate limiting в Redis, блокировка аккаунта после 10 неудач, лимит попыток кода |
| Утечка БД                         | пароли — argon2id; refresh-токены и reset-токены — SHA-256; коды — HMAC с секретом                   |
| Кража refresh-токена              | ротация на каждое обновление; повтор старого токена отзывает сессию                                  |
| Загрузка файлов                   | лимит 5 МБ, декодирование sharp, перекодирование в WebP, случайные ключи                             |
| Утечки в ошибках/логах            | единый формат ошибок без stack trace; pino redaction для cookies/токенов/паролей                     |
| Заголовки                         | Helmet в API; CSP, HSTS, X-Frame-Options, Referrer-Policy в Next                                     |

## Расширяемость

Подготовлены точки расширения (без преждевременной реализации): реальные платежи
(`PaymentProvider`), push/SMS (`NotificationChannel`), real-time трекинг (события
`order.status_changed` → WebSocket-шлюз вместо polling), другие карты (`TILE_PROVIDERS`,
`GeocodingProvider`), несколько точек/зон доставки (расчёт доставки изолирован в
`calculateDeliveryFee`), лояльность (транзакционное создание заказа + аудит).
